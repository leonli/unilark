# Unilark 0.0.3 · 第一版交互改进

2026-09-13。实验版。用户已要求先交付一版可用改进，本版落实 Rich UE 提案的会话面板及部分表单。

## 可以直接使用

- `/`、`/help` 打开命令面板。未知或不完整斜杠命令也回到面板，不作为 Agent 任务执行。
- `/list`、`/sessions` 显示当前会话、项目、中文状态和队列数量；每页 5 项，支持筛选、分页、刷新和点选切换。
- `/status` 改为当前会话详情；`/tasks` 汇总后台任务。详情可以停止、继续、撤销排队项、归档和恢复。
- 点“新建会话”填写标题并创建；工作目录固定在表单打开时，一个表单只创建一次。`/new 标题` 与无参数快捷创建继续兼容。
- 输出、审批和回执显示会话标题、短编号及项目；切换只影响后续普通输入，原队列、引用和按钮继续绑定原目标。

发送 `/list` 即可开始，无需重新配对。机器人后台菜单暂未配置，入口按钮位于消息卡片中。
原生输入框 `/` 自动补全、多会话同时执行、多题问答表单、原生会话自动发现及项目选择表单仍属于后续阶段。
当前同时执行上限为 1，队列卡会显示等待原因。

## 验证和限制

- 本地自动测试合计 97 项：既有 88 项，新增 8 项卡片用户旅程及 1 项官方 SDK 表单到 Hub 的流程。
- 真实 Lark API 1 项通过：会话面板、命令卡、新建表单分别发送并 GET 回读成功，只清理了测试消息。未启动第二个 WebSocket 消费者，未模拟真人点击为真实证据。
- 原有 8 项真实 AGY 回归首轮为 7 通过、1 停止确认超时；该停止用例单独复跑通过。首轮失败证据保留，不能把这次全量回归写成一次全绿。
- 对失败会话连续读取 3 次：AGY 报 `fullyIdle=true`、主流程 idle、无活动步骤/子任务/后台命令，但原生待处理消息数量仍为 2。完整空闲门禁因此继续拒绝确认。这是既有原生停止后队列滞留边界；本次未放宽门禁或自动重投。
- Ruff、mypy、包依赖检查作为构建门禁。真实手机点击、卡片更新时输入草稿表现和布局仍需要在用户实际客户端验收；API 接受不等于手机体验已通过。

每条新增流程及与手册的对应关系见 [E2E-COVERAGE.md](E2E-COVERAGE.md)。
本版未改 AGY 原生协议、并发调度策略、权限有效期或未知结果恢复规则。

## 持久化与回退

新增可选的 `ui_panels`、`ui_actions` 表，保持数据库 schema 2 和既有业务表。
动作固定 owner、消息、目标与允许字段，接收和持久化意图在同一事务；表单提交后关闭旧按钮，停止时再次核对原生运行代次。
新表不包含凭据。表单中的已知应用凭据会被拒绝，标题在展示/创建前脱敏。

升级继续使用现有一致性备份、候选检查与失败回退。兼容回退 0.0.2 时保留全部数据；先等待所有待提交/待确认动作处理完成。
旧程序不支持 UI 按钮，需要使用旧文本命令；再次升级后保留原绑定和选择。

本机发布前另发现旧版一张 `/sessions` 状态快照卡的投递未知；它是只读总览，后续总览已真实送达。
按本机恢复流程接受该旧快照的投递不确定性并保留审计；不声称它未送达，也不重发或删除任务。
具体本机升级与数据保留结果记录在私有 `spike/evidence/ue1-*.json`。
