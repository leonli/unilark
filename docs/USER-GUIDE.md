# Unilark 用户使用手册

适用版本：**0.0.2 实验版**。更新：2026-09-13。

Unilark 让你在 Lark 私聊中使用主机上的 AGY，并接续同一个原生会话。任务由运行 AGY 的主机执行；手机是输入、查看结果和处理审批的入口。

你目前的环境已经安装并配对，可以从下面的快速上手开始。新用户安装见 U17。文中的 `BINDING_ID`、`NATIVE_UUID`、`REQUEST_ID` 等是占位符，使用时替换成实际值，不要原样发送。

已实测环境为 Linux x86_64、Python 3.12、AGY 2.13.0 和国际版 Lark。飞书中国版及其他平台尚未完成真实验收。本文描述当前操作方式；每项操作的测试证据和缺口见 [手册与 E2E 对照](E2E-COVERAGE.md)。

## 先完成一次任务

<a id="u01"></a>
### U01 · 已配置用户快速上手

在 Lark 中打开 **Unilark 机器人私聊**，依次发送两条消息：

```text
/new 使用练习
```

看到“会话已建立”后，发送：

```text
不要调用任何工具，只回复：连接成功。
```

先看到“输入已保存”或输入状态卡，随后看到“AGY 回复”。以实际回复为完成依据；“已保存”和 `ACCEPTED` 都不表示任务已做完。继续发普通文本，会沿用当前选中的会话。

如果没有回复，发送 `/status`；如果机器人完全不回应，按 U15、U20 检查主机和连接。无需重复配对。

## 会话与任务

<a id="u02"></a>
### U02 · 新建会话

发送 `/new 标题`，例如 `/new 周报整理`。机器人准备成功后会显示两种编号：

| 编号 | 用途 |
|---|---|
| “会话”编号，即 `BINDING_ID` | `/switch`、`/resume`，以及维护命令的 `--binding` |
| “原生会话”编号，即 `NATIVE_UUID` | 连接 AGY 原生会话的 `/attach`，以及本机 `history` |

标题是便于识别的名称，不能替代编号。`/new` 会选中新会话；如果只想继续旧任务，直接发送文本或先 `/switch`，避免重复创建。

准备中的输入可以先保存，但必须等会话确认可用才会执行。出现“状态待确认”时先核对，不要反复 `/new`。

<a id="u03"></a>
### U03 · 手机和 AGY 桌面接力

手机新建的会话可以在 AGY 桌面打开，查看原正文和 `Lark · Unilark` 来源。继续在该桌面会话输入，机器人会同步“来自 AGY 的输入”和后续回复；再从手机继续时，先确认选中的是同一会话。

如果任务最初在桌面创建，需要先连接它：

```text
/attach NATIVE_UUID
```

原生编号从 AGY 可取得的会话信息或维护人员处获取。机器人目前不能列出全部未绑定的 AGY 会话，也不能用标题搜索连接。原生会话须有可读历史，并属于已配置的 AGY 实例；空历史不能证明连接成功。

连接成功后保留同一个原生会话。若会话已归档，按 U13 恢复；不要反复 `/attach`。

<a id="u04"></a>
### U04 · 查看和切换会话

发送 `/sessions` 或 `/list` 查看会话编号、工作目录、状态及待提交数量。当前版本 `/status` 也展示这份会话总览，不只显示当前会话。

```text
/switch BINDING_ID
```

看到“已切换会话”后，新的普通消息才会投向这个会话。已保存的任务仍留在原会话，切换不会搬动它们。列表目前没有明确的“当前选中”标记；不确定目标时，先显式 `/switch` 并查看确认卡。

<a id="u05"></a>
### U05 · 引用旧卡片，继续对应的任务

在 Lark 对某张 Unilark 任务或回复卡片使用“回复/引用”，再发送文本。这条消息会发往卡片所属的会话，即使你已经切到其他会话。

引用未知消息、没有会话归属的卡片或已归档会话时，可能收到拒绝提示；机器人不会猜一个会话执行。**引用“AGY 等待回答”卡片时，文本是对问题的回答**，操作见 U11。

<a id="u06"></a>
### U06 · 排队与输入状态

普通文本是一项待提交任务。已有工作运行时，新输入通常先排队；回执会显示请求编号和队列位置。当前调度会检查同一实例的所有已绑定活动会话，因此切到一个空闲会话也不保证立即启动新任务。

| 显示 | 含义及下一步 |
|---|---|
| 输入已保存 / `QUEUED` | 主机已保存，尚未交给 AGY；等待或按 U08 撤销 |
| `SUBMITTING` | 正在提交，不能当作未执行来重发 |
| `ACCEPTED` | AGY 已接受输入；继续看回复和运行状态 |
| `UNKNOWN` | 无法确认是否执行；按 U16 核对 |
| `REJECTED` | 输入被拒绝，或尚未提交时被本地撤销；结合相关提示判断 |
| `DISMISSED` | 维护人员接受了不确定性并停止跟踪；不代表没执行 |
| 队列 `PAUSED` | 暂停提交；处理原因后，按 U09 显式继续 |

排队不能保证所有桌面与手机输入严格按发送时间串行执行。请避免多端同时反复提交同一个动作。

<a id="u07"></a>
### U07 · 给当前任务补充要求

任务运行中，若要影响当前任务，使用：

```text
/steer 最终结果请用中文，并附上结论依据。
```

普通文本会排为下一项，`/steer` 才表示补充当前工作。补充不会撤销已经完成的修改，也不保证立刻打断正在运行的命令。实例不支持时会明确提示；不要把它当作停止或撤销。

<a id="u08"></a>
### U08 · 撤销尚未提交的输入

从输入回执复制“请求”编号，发送：

```text
/cancel REQUEST_ID
```

成功时看到“已撤销尚未提交的输入”。如果已经提交、正在执行或结果未知，会提示未撤销。要停止已运行的任务，使用 U09；这里的请求编号不是会话编号。

<a id="u09"></a>
### U09 · 停止任务，随后继续队列

点击对应运行状态卡上的“停止并暂停队列”，或先切到目标会话后发送 `/stop`。

先看到“正在停止”，之后应看到“已确认空闲”。前者表示停止意图已经保存，后者才表示 AGY 确认空闲。停止不会撤销此前的文件、命令或其他副作用。

停止后队列保持暂停。准备好让尚未提交的任务继续运行时，发送 `/continue`。遇到未知结果，须先按 U16 处理；`/continue` 不是忽略错误或重新执行已中断任务的命令。

<a id="u10"></a>
### U10 · 处理工具审批

出现“AGY 请求批准”卡片时，核对会话和操作内容，然后点击“仅本次允许”或“拒绝”。“仅本次允许”不等于永久授权。

卡片显示“决议已提交”后，继续查看 AGY 的实际执行结果；允许不保证命令执行成功。请求改变、按钮已使用、身份不符或卡片到期时，旧按钮不能继续授权。

审批从网关建立请求起约 5 分钟有效，未处理将提交拒绝。断线时可能延迟到恢复后处理。操作内容过长可能截断，需要看完整内容时回到 AGY 桌面核对。

当前远程审批只覆盖已验证的 `run_command` 权限请求；其他类型可能需要桌面操作。工具是否需要审批仍由 AGY 自身设置决定。

<a id="u11"></a>
### U11 · 回答 AGY 的问题

看到“AGY 等待回答”卡片时：

- 单个单选题且选项不超过 5 个：可以直接点选项。
- 自由文本、更多选项或多个问题：**引用这张问题卡片**回复。
- 多个问题：按卡片顺序每题一行；多选项用英文或中文逗号分隔，选项文字与卡片一致。

例如卡片依次问颜色、需要的工具、补充说明，可以引用它回复：

```text
蓝色
工具一, 工具二
请优先保证可读性。
```

不要自行加题号，除非题号就是你的答案。不匹配选项的文字会作为自由填写内容提交，不会按近似文字猜选项；重复选项标签也会按自由填写处理。

点击“取消问题”只取消这次提问，不等于停止整个任务。约 5 分钟未处理将取消问题。已经回答或到期的旧问题卡片不能再次作答；未引用卡片的普通文字会排为新任务，可能继续等待当前问题解决。

较长问题卡片可能截断。遇到看不全、复杂格式或不支持的交互，转到原生桌面处理。该功能的原生问答已实测，真人 Lark 问答流程仍待完整验收。

<a id="u12"></a>
### U12 · 为后续新会话选择工作目录

先确认目录存在于 **运行 AGY 的主机**，再发送：

```text
/cwd /home/yourname/projects/demo
/new demo任务
```

以上是两条消息；目录示例需要替换。`/cwd` 不创建目录，也不是手机上的文件路径。看到“新会话工作目录已设置”后，新建会话会记住这个目录；已有会话保持原目录。之后再改 `/cwd`，也不改变已经收到的 `/new`。

工作目录用于选择项目，不是限制 Agent 文件访问的沙箱；工具授权仍由 AGY 决定。

<a id="u13"></a>
### U13 · 归档和恢复会话

先 `/switch BINDING_ID`，确认任务已空闲、没有排队或未知输入，再发送 `/archive`。
机器人停止同步该会话并暂停队列，但保留原生历史。归档当前会话后，新的普通消息需要先选择或创建另一个会话。

恢复时发送 `/resume BINDING_ID`。恢复成功会选中原会话，继续同步，但队列仍暂停；需要提交新任务时再 `/continue`。

`/resume` 只恢复已归档会话，不能修复所有不可用状态。当前版本不能恢复没有原生历史的空会话；建议真正使用过的会话再归档。归档不删除历史，也不释放原生项目文件。

<a id="u14"></a>
### U14 · 帮助、身份与能力

| 命令 | 用途 |
|---|---|
| `/help` | 查看常用手机命令 |
| `/whoami` | 查看当前 owner 的用户编号，不是切换账号 |
| `/capabilities` | 查看已配置 AGY 实例支持的能力及限制 |
| `/status` | 查看各会话、队列和投递总览 |

未知的斜杠命令会被拒绝，不作为普通任务执行。当前版本没有手机端删除历史、切换模型、增加 owner 或接入其他引擎的命令。

## 遇到中断时

<a id="u15"></a>
### U15 · 断网、程序退出或主机离线

只退出手机 Lark 或关闭终端，不会主动停止已经托管的网关。网关停止后，AGY 中已开始的任务仍可能继续。

网络恢复后，网关会重新连接并补投递已保存结果。曾实测限网 11 分钟后自动恢复；本次恢复网络到最终回读约 3 分钟，这不是即时恢复时限承诺。

离线期间发往机器人的消息是否补发由 Lark 决定。没有收到“输入已保存”时，先恢复连接并核对状态及原生历史，再决定是否明确重新提交，避免同一动作重复执行。

“AGY 连接降级”表示暂时无法读取原生状态，新任务不会自动提交或换到替代会话。维护人员恢复原实例后再检查。主机睡眠、断电或登录失效期间，不能保证执行和通知；整机重启/睡眠恢复尚未实测验收。

<a id="u16"></a>
### U16 · 结果未知或卡片投递失败

出现 `UNKNOWN` 时，保存对应会话、请求或卡片编号。先查看 AGY 是否已经收到输入、工具是否产生效果，以及 Lark 中是否已有卡片。不要删除数据库，也不要把没收到回执当作没执行。

这是维护人员的本机处理流程：

```bash
unilark recovery list
unilark service stop --system
unilark recovery acknowledge input REQUEST_ID --acknowledge-possible-execution
unilark service start --system
```

这里按当前本机的系统服务举例；用户服务省略 `--system`。只有核对后决定接受不确定性，才执行 `acknowledge`。结果保留为 `DISMISSED`，队列保持暂停，原动作不会自动重发。控制操作用 `control EVENT_ID`，投递用 `card CARD_ID`。

新建或连接会话的未知结果经裁决后可能仍是不可用状态，不能承诺 `/continue` 就能修好，需要维护人员继续核对原生绑定。

`BLOCKED` 表示投递被阻塞。修复权限等原因后，只有带已知消息编号的卡片更新可使用 `unilark retry-delivery CARD_ID`。结果未知的新卡片不会自动重建。

## 首次安装与日常维护

本节在运行 AGY 的主机终端执行，不要把 `unilark ...` 当作 Lark 消息发送。示例假定安装入口已加入 PATH；否则用 `~/.local/bin/unilark`。全局参数 `--config`、`--state`、`--credentials` 放在子命令前。

<a id="u17"></a>
### U17 · 新用户首次安装与配对

已有安装的当前用户跳过本节。新环境需要 Python 3.12 和 venv、已安装并登录的指定 AGY 实例及现有项目。先验证并安装离线包：

```bash
sha256sum -c SHA256SUMS
tar -xzf unilark-0.0.2-linux-x86_64.tar.gz
python3 unilark-0.0.2-linux-x86_64/install.py
```

根据包内 `config.example.toml` 准备实例配置，再运行：

```bash
~/.local/bin/unilark --config /private/path/agy.toml setup
```

在本机隐藏输入 App Secret。按照 [Lark 配置指南](LARK-SETUP.md) 完成对应区域的机器人、权限、长连接事件及应用发布/本人可用范围。

配对窗口内，在机器人私聊发送终端给出的 `/pair 配对码`，然后回本机核对候选身份并确认。约 5 分钟过期后重开配对窗口；只知道配对码不能代替本机确认。

setup 可以重复执行，保留已配置凭据与 owner；不会自动完成外部 AGY 登录、控制台配置或全部真人验收。当前新用户安装仍包含这些人工步骤。

<a id="u18"></a>
### U18 · 前台验收后交给后台服务

先在未运行第二个网关的环境执行 `unilark --config /private/path/agy.toml run`。完成 U01、U03、U10、U09 的真实操作，再按照 [安装指南的证据保存步骤](install.md#保存验收证据) 使用 `acceptance verify`。

该命令会核对原生会话和实际 Lark 消息，但其中的桌面查看、桌面输入、工具效果确认需要你确实完成，不能只填标志跳过操作。

退出前台进程后安装后台服务。默认用户级服务：

```bash
unilark --config /private/path/agy.toml service install
unilark service start
unilark --config /private/path/agy.toml setup --non-interactive
```

无用户服务总线时，可显式采用系统服务，上面三个命令分别添加 `--system`。系统安装需要已有管理员权限，以当前用户运行网关。

setup 的 `ready` 要求实时健康、既有验收记录及后台服务进程/配置匹配；只看到前台能运行还不算交接完成。当前用户的系统服务已完成交接，无需再次安装。

<a id="u19"></a>
### U19 · 查看、重启或停止后台网关

当前本机使用系统服务：

```bash
~/.local/bin/unilark service status --system
~/.local/bin/unilark service restart --system
~/.local/bin/unilark service stop --system
~/.local/bin/unilark service start --system
```

停止网关不等于停止 AGY 任务；需要停任务时先用 U09。网关重启应保留历史和队列，不会自动重新提交未知输入。

当前主机另有独立 AGY 和虚拟桌面服务。它们的运行与登录条件见 [本机维护说明](OPERATIONS.md)。用户级服务能否在注销后持续运行取决于系统配置，不能由当前系统服务的实测结果推断。

<a id="u20"></a>
### U20 · 诊断、日志与导出

当前主机可以直接使用：

```bash
~/.local/bin/unilark --config /home/lileon/doc/unilark/spike/runtime/unilark.toml doctor --check-api
```

其他安装使用自己的配置路径。退出码 0 表示当前检查通过，2 表示未就绪；查看 `repairs` 的建议。历史 `acceptance` 通过不代表现在在线。

```bash
unilark --config /private/path/agy.toml sidecar check agy
unilark diagnostics --output ~/.unilark/diagnostics.json
unilark audit --output ~/.unilark/audit.json
```

导出目录必须已存在；诊断/审计文件不含消息正文和凭据，但仍有会话定位信息。日志默认位于 `~/.unilark/gateway-app.log`，达到约 5 MB 轮转，保留 3 个备份。

需要显式查看原生正文时，用 `unilark --config /private/path/agy.toml history NATIVE_UUID`。原始任务正文仍属于敏感数据，不应把历史、数据库或日志直接公开上传。

`doctor --connect-lark` 仅在网关停止后做独占连接检查；不要同时启动第二个 `run`、`pair` 或长连接探测。

<a id="u21"></a>
### U21 · 备份、升级和回退

升级前先让原生任务空闲，并处理排队和未知请求。备份使用新的文件名：

```bash
unilark backup --output ~/.unilark/backups/before-upgrade.db
unilark --config /private/path/agy.toml upgrade /path/to/new-bundle --system
unilark --config /private/path/agy.toml rollback --system
```

备份包含任务正文，需要妥善保存；不会覆盖同名旧备份。升级需要**其他版本的已校验包**，不能拿当前 0.0.2 包再次覆盖自己。自定义安装添加 `--prefix`；用户服务省略 `--system`。

升级流程会检查任务状态、备份数据库、在副本检查迁移，再切程序和核验健康。失败时根据数据库兼容性决定能否切回前版。

回退只切换兼容程序，不用旧备份覆盖升级后新增的数据。当前 0.0.2 使用 schema 2，不能自动回退到只认识 schema 1 的 0.0.1。完整限制见 [安装维护指南](install.md#升级回退和卸载)。

<a id="u22"></a>
### U22 · 卸载程序并保留数据

处理运行、排队和未知任务后，在主机执行：

```bash
unilark --config /private/path/agy.toml uninstall --system
```

按实际服务范围和安装目录调整 `--system`、`--prefix`。此命令移除匹配的网关服务、程序版本和启动入口，保留状态、凭据、备份、外部 AGY、登录及 workspace。

`service uninstall` 只卸载网关服务；`uninstall` 才是程序卸载。当前版本没有一键清除全部业务数据的选项，也不会清除本机独立的 AGY/桌面环境。

<a id="u23"></a>
### U23 · 使用范围与信息保护

当前版本面向一个已在本机确认的 owner、一个选定的 AGY 实例和私聊文本。群消息、其他身份或不支持的附件不会作为正常任务执行；图片、文件、群聊协作和其他 Agent 引擎不在本版使用范围内。

不要把 App Secret 或其他敏感凭据发给机器人。网关拒绝保存已知应用 Secret，并对常见敏感格式脱敏，但不能保证识别所有未知秘密。AGY 自身的文件访问和工具权限仍然有效，选择一个工作目录不等于隔离其他文件。

本版仍是本地实验版。后续开发和需要补齐的用户流程，见 [测试对照与后续计划](E2E-COVERAGE.md#后续开发顺序)。
