# Unilark · Rich UE 改进提案

日期：2026-09-13。基线：0.0.2 / `ef73c8a`。状态：**待评审的产品方案，尚未上线**。

目标：在 Lark 手机上，不背命令、不复制会话 UUID，就能知道正在和谁说话、切换任务、处理问答，以及管理多个后台会话。

## 1. 推荐方向

把 Unilark 的主要入口改成 **会话面板 + 可操作的任务卡片**，文本命令保留为快捷方式。所有入口调用同一组操作；按钮和命令不会各自形成一套行为。

| 你的要求 | 推荐体验 | 实现边界 |
|---|---|---|
| 输入 `/` 自动补全 | 原生输入联想作为首选目标；同时提供机器人菜单和卡片命令面板 | 输入尚未发送时的联想依赖 Lark 客户端开放能力，不能用“发送 `/` 后回卡片”冒充 |
| 命令都是交互卡 | `/list` 打开会话面板；列表明确显示当前会话，每项可以切换、查看任务；其余命令打开对应卡片或表单 | 常见操作不要求输入 UUID；参数命令继续兼容 |
| 管理并行会话 | 当前会话负责输入路由，多个后台会话独立执行、排队、问答和停止 | 当前代码全局串行，需要改调度并实测 AGY；不是只改列表样式 |

推荐默认：**最多同时执行 2 个会话，同一项目目录排队**。这项默认值只有在真实 AGY 并发验收通过后启用；此前面板明确显示“同时执行上限：1”。

平台核验和官方出处：[Lark Rich UE 调研](UE-PLATFORM-RESEARCH.md)。可点击的流程原型位于本地独立分支 `prototype/rich-ue`，见第 9 节。

## 2. 入口：三个按钮覆盖日常使用

机器人菜单建议只放 **会话 / 新建 / 任务**。帮助和诊断在命令面板中，减少手机首屏拥挤。菜单是 Lark 提供的入口，不承诺在聊天顶部固定自定义工具栏。

命令面板按“会话、任务、设置”分组，每项包含中文说明和动作。例如：

```text
你想做什么？
当前：修复登录 · 正在运行

[查看和切换会话]  /list
[新建会话]        /new
[查看当前任务]    /status
[补充当前任务]    /steer
[暂停当前会话]    /stop
[更多设置与帮助]
```

`/` 的能力分两层验收：

1. **原生自动补全**：键入 `/`，未发送即出现应用命令；继续输入能缩小候选。必须在真实国际版 Lark 的手机端验证。
2. **可实现的发现入口**：点机器人菜单，或发送 `/` / `/help` 打开命令卡片。发送 `/li` 时可返回“你可能想查看会话”及可点击入口；未知命令不作为任务交给 Agent。

第二层能解决“不记命令”，但不能勾选第一层的验收项。如果官方能力不能满足输入联想，另行评估应用内输入页；这一轮不为补全单独引入一个新网页聊天端。

本次核查未找到普通机器人注册原生 `/` 联想的公开接口，因此第一层当前记为**未解决的平台依赖**。菜单需要开发者后台配置、订阅事件并发布应用版本；实施时先把三个入口及其动作准备好，届时只集中列出确需你操作的后台步骤，无需重新提交凭据。

## 3. `/list`：从清单变成会话面板

```text
我的会话                                  刚刚更新
当前输入 → 修复登录
执行中 2 · 待你处理 1 · 排队 2

[全部] [待处理] [已归档]           [新建会话]

● 当前  修复登录
网站项目 · 正在运行 · 后续排队 1
正在检查登录测试
[查看任务] [停止并暂停队列]

        编写用户手册
文档项目 · 等待你回答
需要确认手册的读者
[切换到此会话] [去回答]

        整理测试报告
网站项目 · 排队
等待“修复登录”释放项目目录
[切换到此会话] [查看队列]

[上一页]                第 1 页              [下一页]
```

- 首屏最多 5 个会话；当前会话置前，其后待处理、运行中、最近活动。筛选和翻页后仍在顶部显示当前输入目标。
- 标题、项目简称、状态、下一步操作是主要信息。完整路径、原生编号和请求编号放到详情/诊断页。
- 重名会话增加稳定短编号，例如“修复登录 · 7K2”，不让用户依靠列表序号识别。
- 切换后立即显示“已切换到：编写用户手册；下一条普通消息将发到这里”，并更新面板的当前标记。
- **切换不会停止原会话，也不会转移已保存任务。** 查看某个会话的详情也不会自动切换。
- 面板刷新优先更新已知消息，不每次状态变化都发送新卡。重新发送 `/list` 可以拿到最新面板，旧面板的操作要重新校验。
- 无会话时展示“新建会话 / 连接已有会话”；离线时展示最后更新时间和“状态待更新”，不显示虚假的绿色在线。

“执行中”和“待你处理”允许重叠，不能把三个数字相加当作会话总数。详情同时显示**执行状态**和**队列状态**，例如“仍在运行 · 队列已暂停”。

## 4. 命令卡片化：每次操作都有下一步

| 入口 | 卡片行为 | 不再要求用户做的事 |
|---|---|---|
| `/`、`/help` | 分类命令面板，中文说明，直接操作 | 背完整命令表 |
| `/list`、`/sessions` | 会话面板、当前标记、筛选、分页、切换 | 复制 UUID 后 `/switch` |
| `/switch` 不带参数 | 同一会话选择器 | 猜命令参数 |
| `/new` 不带参数 | 填标题、选择已配置/最近工作目录；提交时明确“创建并切换” | 先发 `/cwd` 再新建 |
| `/new 标题` | 保留一条命令快速创建，回卡显示标题/项目及下一步 | 为熟练用户增加步骤 |
| `/attach` 不带参数 | 展示**可验证可连接**的原生会话；提供刷新与手动编号兜底 | 默认从桌面抄编号；若原生枚举不可靠，明确暂不可发现 |
| `/status` | 当前会话详情，正在做什么、排队内容、下一步动作 | 从全局列表猜当前任务 |
| `/tasks`（新增） | 所有活动会话的运行任务与待处理事项 | 逐个切换查进度 |
| `/steer` 不带参数 | 固定目标会话的补充要求表单；同时提供“排为下一项” | 混淆补充当前任务和创建后续任务 |
| `/stop` | 明示目标的停止回执，“正在停止 → 已确认空闲”；队列保持暂停 | 把提交停止当成任务已结束 |
| `/continue` | 展示队列将继续提交的内容，执行后更新状态 | 误以为恢复队列会重跑中断任务 |
| `/cancel` 不带参数 | 当前会话队列，每条未提交任务有“撤销” | 复制请求编号 |
| `/archive` | 可归档时显示目标并确认；运行中展示原因与“查看任务” | 看技术状态猜为什么失败 |
| `/resume` 不带参数 | 归档列表，选择恢复；显示“已恢复，队列仍暂停”及继续入口 | 记归档会话编号 |
| `/cwd` 不带参数 | 后续新会话的项目选择；完整路径放在确认摘要 | 误认为修改现有会话目录 |
| `/whoami`、`/capabilities` | 设置/诊断卡，显示中文说明、支持范围、返回入口 | 阅读原始内部枚举 |

`/status` 从全局总览改为当前会话详情是明确的行为变化；全局入口统一到 `/list` 和 `/tasks`。手册同步迁移说明。

### 任务详情与输出

每张任务卡都有稳定上下文：**会话标题 · 项目简称 · 本次任务**。后台输出也带同样的标识，避免两个任务的回复混淆。

```text
修复登录 · 网站项目
本次任务：处理移动端登录失败
状态：正在运行                  后续任务：2 项

[补充要求] [停止并暂停队列] [查看队列]

后续第 1 项：补一份变更说明          [撤销]
后续第 2 项：整理回归结果            [撤销]
```

- 普通消息：回执为“已交给『修复登录』”或“已排为下一项 · 前面 1 项”，按真正的提交状态显示。
- 只用原生可观测的摘要说明进度；没有进度数据时不造百分比、剩余时间或工具调用记录。
- 新任务、需处理、完成、失败可以产生通知；细碎进度更新原卡。默认不持续刷屏。
- 长结果按有序分块或分页展示全文。审批不能只展示一个被截断的关键命令却让用户盲点允许；完整内容不可取得时引导到原生桌面处理。

### 问答和审批

- 单选用按钮/下拉，多选用多选控件，自由回答用输入框，多题使用带题名的表单；不再要求按题序“每题一行”拼协议。
- 表单带会话、任务和有效状态；提交后原卡显示已回答并关闭旧动作。验证不通过时保留可以安全恢复的输入并标明具体字段。
- 审批仍区分“仅本次允许 / 拒绝”，过期不能重用。点击旧卡、重复点击、切换后回答，都只作用于卡片原来的问题。
- 手机客户端不支持某控件时，保留引用回复兜底；真实手机渲染和回调通过后才替换现有流程。

## 5. 并行会话的行为约定

### 三个概念各司其职

| 概念 | 含义 | 用户可做什么 |
|---|---|---|
| 当前会话 | 下一条未引用的普通消息的目标，最多 1 个 | 切换；不会影响其他任务运行 |
| 运行中的会话 | AGY 已在处理任务，可以有多个 | 分别查看、补充要求、停止 |
| 会话内队列 | 已固定归属的后续输入 | 查看和撤销未提交项，停止后显式继续 |

引用旧任务卡回复会固定发往旧任务所属会话；回执明确显示目标，当前会话不随之变化。引用问题卡则回答该问题，不新建任务。

### 推荐调度策略

1. 同一会话一次只提交一个普通任务，后续输入 FIFO 排队。
2. 不同已确认项目目录、原生状态独立可观测的会话，可以同时执行；建议上限 2。等待原生问答/审批的会话暂计入上限，避免用“等待”绕过并发限制。
3. 同一目录、父子目录或已知共享写入范围的会话默认排队。空目录、符号链接和无法确定归属不能被当成已隔离目录。确需同项目并行时，后续可用独立 worktree；首轮不自动创建隔离副本。
4. 排队解释具体原因：“等待本会话结束”“等待网站项目空闲”“同时执行名额已满”“队列已暂停”“状态待确认”。
5. 跨会话公平选择可启动队列，不让长队列永久挤占另一个项目。
6. 对单会话的停止、问答和审批优先处理；一个较慢的状态读取不能长期拖住其他会话的操作响应。
7. 状态不确定的会话暂停后续提交、保留可能占用的执行名额并锁住相关项目。能证明独立的另一项目可继续；实例掉线或无法定位影响范围时暂停该实例的新提交。
8. 不把未知执行结果包装成“一键安全重试”，也不自动重发。恢复连接后先核对，停止确认前不释放资源占用。

不同目录不构成文件访问沙箱；Agent 仍可能操作目录之外的内容。这里只协调 Unilark 能识别的冲突，不声称隔离桌面端或外部工具的写入。

真实并行上线门槛：两个真实 AGY 原生会话的执行时间区间确实重叠，且停止 A、回答 A、A 的不确定结果不会错误控制 B。测试替身中的并发不能替代这项证据。

## 6. 卡片交互的技术约束

这些约束留在实现里，普通用户只看到清楚的目标和结果。

- 命令/菜单/卡片回调归一为同一应用操作。补齐 Lark adapter 的菜单事件、select 选值和 `form_value` 解析；不让 SDK 数据结构扩散到核心模块。
- 导航类动作可重复，执行类动作带一次性标识和持久化去重。卡片保存 owner、消息、目标会话/请求、允许值与状态版本；服务端重新校验，不能信任客户端提交的目标编号。
- 面板含多个会话，因此面板本身不作为任意一项任务的引用目标。只有会话详情、具体任务/问答卡具有固定归属。
- “停止”固定到卡片对应的运行代次；任务已换成下一次时，旧停止按钮拒绝并展示最新卡，不误停新任务。“撤销”也固定具体排队项。
- 从旧表单创建新会话/提交任务，不读取此刻全局选择作为目标。若创建过程中选择已改变，完成回执提供“切换到新会话”，不在后台突然抢回选择。
- 多字段表单必须校验全部题目和完整问题指纹；有缺项或旧版本时不提交半份答案。过期恢复表单必须重新验证原生问题。
- 更新同一张卡合并状态变化，初始建议普通进度最多 2 秒一次；这是本产品节流目标，不是 Lark 平台额度声明。终态/需操作优先，429 按实际回退，离线恢复后显示数据时间。
- 卡片回调在平台要求的 3 秒内确认，原生长操作异步执行。菜单事件没有聊天 ID，按已绑定的 app/tenant/open ID 找到 owner 后路由，不能放宽身份校验。
- 官方卡片更新有发送后 14 天期限；过期面板由显式打开操作生成新卡，不假设一张卡永久可改。表单/JSON 版本按实际手机客户端能力验收，基础按钮先沿用兼容布局。
- 旧面板点击切换先校验目标仍可用；若已归档或不可用，提示并刷新。重复卡片创建结果未知仍不盲目重发。
- 新的应用动作与任务状态展示提取为小模块；先保留现有安全账本和 outbox，不把所有卡片逻辑继续堆进 `Hub`。

## 7. 分阶段实施和退出条件

| 阶段 | 交付 | 退出条件 |
|---|---|---|
| UE-1 · 先把日常操作做顺 | `/list` 会话面板、当前标记、按钮切换、详情/队列、明确的输出归属；`/` 和帮助命令卡 | 不复制 UUID 完成查看→切换→发送→查看队列→撤销；切换不改变旧任务目标；完成真实 Lark 回调验证 |
| UE-2 · 表单与任务卡 | 新建、项目选择、归档恢复、补充要求、结构化问答；菜单入口按平台能力接入 | 手机完成新建→运行→回答→停止→继续；重复和过期动作不会二次执行；保留参数命令回归 |
| UE-3 · 真正并行 | 每会话调度、公平选择、目录冲突/容量管理、跨会话任务页 | AGY 双会话真实重叠、相互控制隔离、同项目排队和断线恢复全部通过；否则保持上限 1 并说明 |
| UE-4 · 收尾验收 | 用户手册改为卡片流程、E2E 对照、升级/回退材料 | 每条手册旅程映射实际测试/真机证据；输入时 `/` 补全单独标记，不用替代入口虚假结项 |

UE-1 不必等待输入框联想能力，也不必先开放多会话同时写。UE-3 要修订原 PRD 的全局保守调度约束，记录新适用范围和验证证据。

## 8. E2E 从用户旅程出发

下表是**拟新增的验收场景**，没有声称已经实现或通过。当前覆盖基线见 [E2E-COVERAGE.md](E2E-COVERAGE.md)。

| ID | 用户旅程与期望 | 自动验证与真实验证 | 对应当前手册 |
|---|---|---|---|

| R02 | 菜单/发送 `/`/帮助打开同一命令面板；未知命令给建议，不启动任务 | 命令/菜单回调至 Hub；真实菜单点击 | U14 |

| R04 | A 已排任务，切 B 后旧队列不变；引用 A 旧卡仍进 A | 扩展已有引用绑定回归，验证卡片上下文 | U04/U05 |
| R05 | 面板分页、筛选、空列表、重名、已归档目标和旧按钮 | 边界数据走完整卡片动作流程；手机长标题目检 | U04/U13 |

| R08 | 停 A 后显式继续队列；旧 A 运行卡不能停 A 的下一任务或 B | 原生停止次数/目标与运行代次；真实 AGY 双会话控制 | U09 |

| R10 | 不同项目 A/B 同时执行，输出可辨认，第三项显示名额等待原因 | 调度回归 + 真实 AGY 两区间重叠证据；Lark 输出核对 | U06/U07 |

| R12 | A 状态未知不重发，独立 B 可运行；实例未知时停止新增提交 | 故障注入区分会话/项目/实例；真实恢复验证 | U15/U16 |
| R13 | 弱网/重连/卡片更新限流后，最新面板一致，按钮不过界 | 受控投递故障 + 有限真实 Lark 恢复旅程，不混称真实 429 | U15 |

真实 Lark 验收应沉淀为可重复的测试入口与脱敏证据，不继续只靠一次性私有脚本。平台无法自动化的手机输入联想/视觉验收单列人工步骤，不能用本地 HTML 原型替代。

## 9. 可点击原型与评审范围

原型：`prototype/rich-ue` 分支的 `docs/prototypes/rich-ue.prototype.html`。
本机文件：[打开交互流程原型](../../ue-prototype/docs/prototypes/rich-ue.prototype.html)。双击即可使用，不安装依赖、不连接生产、不保存输入。

演示问题：用户能否区分“当前会话”和“后台执行”，并理解切换、引用、等待同项目和停止后继续的效果。它模拟推荐的并发上限 2；不是已经通过 AGY 验收的声明。页面外侧的状态说明、模拟按钮和导览属于原型工具，不是要塞进 Lark 的产品 UI。

建议评审顺序：先体验切换和旧卡引用，再体验两个项目并行与同项目排队，最后体验旧卡回答和停止。原型代码留在独立分支，主分支只保留方案、证据和后续通过验收的实现。

当前建议是按 UE-1 → UE-2 → UE-3 → UE-4 推进。评审后才把此处的推荐策略视为定稿；现有 0.0.2 运行服务与发行包未改变。
